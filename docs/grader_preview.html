What the LLM judge would say about each fixture

A dry run of the grading prompts over all 14 hand-written fixtures — before spending any compute. Each card shows the question, the chatbot's answer, and the simulated grader output: every rubric item marked pass/fail with a one-line justification, the cited sources classified, the correctness / sourcing / citing split, and the points. Read it as the JSON the judge returns, rendered for humans. If a verdict here looks wrong, that's a prompt to fix — not a real run.

How to read a card

  • F# = a required fact; ▲ marks a critical item (harmful / false-attribution).
  • SRC = cited a primary/official source. LANG = the answer actually reflects that source (catches post-rationalized citations).
  • Facets — correctness / sourcing / citing come apart on purpose, so a right-but-unsourced answer and a sourced-but-wrong answer score differently.

Two checks the LLM does not do

  • Citation exists — code resolves each URL (HTTP 200). A dead URL auto-fails that citation. See 16.6.
  • Deep support — code scrapes the page and NLI-checks it against the claim. First pass leans on the LLM's LANG read.
  • Judge runs at temperature 0, using only the response + supplied ground truth — no outside knowledge.
