**Stall diagnosis + self-heal (the real robustness fix).** Runs kept stalling at ~30/model (both providers, clean rep boundary). Root cause found in raw-completions: ChatGPT captured an EMPTY completion (just the `resume_conversation_token` preamble, then the stream cut off) → code's `!hasAnswer && !isError` branch treated it as "keepalive, wait" → held `inflight` forever → serial queue frozen (Claude blocked behind it). It only resumed when the 180s timeout errored it (no retry existed). The empty/aborted stream itself is triggered by either a backgrounded tab (ChatGPT aborts on hidden) or — my fault — the per-question cookie trim deleting `oai-*` (device) cookies. Fixes: (1) softened trim to analytics-only denylist, never OpenAI/CF/auth; (2) **self-heal**: mark `emptyAt` on empty captures, and in `tick()` re-ask a stalled item (aborted ≈20s / hard timeout 90s) up to 2× then error-and-continue — so one bad answer can never freeze a run again; lowered default timeout 180s→90s; added `RUN.stallRetries`. BUILD → 2026-07-10-h. Complementary root-cause prevention still on the table: visibility shim so backgrounding can't abort streams.
