**Parallel capture: one window per provider + per-provider pause (BUILD 2026-07-11-e).**
The serial one-provider-at-a-time design existed because backgrounded TABS abort
streams (ChatGPT/Gemini) — but the active tab of an UNFOCUSED window stays
`visible`. So ensureTab now gives each provider its OWN window (adopting/moving an
existing tab if it shares a window); streams flow in parallel, only the submit is
serialized (typing needs OS focus; max one submit per 4s tick → staggered, ~Nx
throughput). Risk noted: a provider that checks window focus would abort — stall
detector + tripwire will surface it.
Per-provider ⏸/▶ (user request, for grok account swaps): PAUSE_PROVIDER freezes
one provider (inflight still lands, no new submits) while the rest run;
RESUME_PROVIDER clears its backoff/fail counters so the fresh account is asked
immediately. Popup: pause/play button + "paused" tag per provider row, paused
rows dimmed, their retries dropped from the ticker. Screenshots verified.

**Harvest reliability rebuild + popup UI redesign (BUILD 2026-07-11-a).**
User hit a failed Gemini question mid-harvest and asked: is a failed question
guaranteed to be retried? It wasn't — `doneSetFor` counted ERROR records as done,
so a failure permanently occupied its slot (the self-heal only retried 2x live).
Rebuilt the runner around a completion guarantee:
- Done = OK record only. Error records stay queued; unified `failBackoff` re-asks
  with exponential backoff (15s → 5min cap; capacity errors ≥60s; first aborted-
  stream re-ask fast at 3s). Nothing is ever silently skipped; run completes only
  when every item has an OK answer (or user stops).
- `resumeFromStorage`: "Resume missing" button re-boots the stored run under its
  ORIGINAL runId — items with OK records skip, gaps re-ask.
- Overview now returns per-item states; export summary lists MISSING itemKeys.
- Popup redesigned: provider chips, per-provider progress bar + 15-wide dot grid
  (green ok / amber retrying / blue asking / grey queued), retry ticker.
User verdict on the redesign: "absolutely awful" — needs a visual iteration loop
(screenshot or Playwright MCP + Node) before another attempt.
